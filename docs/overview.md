# Обзор

## Что это

`backend` — сервис генерации видео-сцены по паре «сценарий + коллекция персонажей». Клиент присылает
текстовый сценарий и id коллекции персонажей; сервис генерирует изображение сцены (с учётом персонажей
коллекции, чьи имена встречаются в тексте сценария, и их референсных изображений), сохраняет его в
хранилище, а затем оживляет в короткое видео через провайдера xAI Grok Imagine. Отдельно есть эндпоинты для
создания персонажей и коллекций персонажей, а также «сырые» прокси к провайдерам DeepSeek и xAI.

## Домен

Термины домена определены в [`../CONTEXT.md`](../CONTEXT.md) — единственном глоссарии проекта, здесь они
не переопределяются, только перечисляются как карта: сценарий (scenario), коллекция персонажей (character
collection), сцена (scene), изображение сцены (scene image), видео сцены (scene video), конвейер создания
видео (create video pipe), хранилище артефактов (storage), ссылка провайдера на видео (provider video
URL), запись о видео в Redis, TTL записи.

## Стек

По `package.json`:

- **NestJS 11** (`@nestjs/common`, `@nestjs/core`, `@nestjs/platform-express` `^11.0.1`) — HTTP-фреймворк.
- **TypeORM `^0.3.31` + Postgres** (`pg` `^8.23.0`) — хранение сущностей, `@nestjs/typeorm` `^12.0.1`.
- **Redis через `ioredis`** — кэш конвейера создания видео. Обратите внимание:
  `ioredis` в `package.json` не объявлен (используется, но не является зависимостью проекта) — см.
  [`known-issues.md`](./known-issues.md).
- **S3-совместимое хранилище** через `@aws-sdk/client-s3` `^3.1131.0` — артефакты (изображения) сцены и
  персонажей.
- **Провайдеры моделей через Vercel AI SDK** (`ai` `^7.0.99`): `@ai-sdk/deepseek` `^3.0.39` (текстовые
  промпты, DeepSeek) и `@ai-sdk/xai` `^4.0.58` (текст, изображения, видео, xAI Grok Imagine).
- **Валидация** — `class-validator` `^0.15.1` / `class-transformer` `^0.5.1`, применяются глобальным
  `ValidationPipe`.

## Зрелость проекта

Ранняя стадия. Основной путь («создать сцену») реализован и синхронный. `GenerationItemModule` — заготовка
под будущий асинхронный конвейер с отслеживаемым статусом (`status`, `currentStep`, `error`): сущность
полноценная, но сервис умеет только создать запись, никто статусы не переключает. Подробности — в
[`data-model.md`](./data-model.md) и [`known-issues.md`](./known-issues.md).
